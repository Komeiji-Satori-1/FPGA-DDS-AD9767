# 设计决策记录

## 2026-07-15

### 决策 1：项目定位

项目定位为：

```text
双通道 AD9767 DDS 任意波形发生器 FPGA 核心
```

原因：

1. AD9767 本身主要是并行 DAC 输出接口，不是带复杂配置寄存器的外设。
2. 项目核心复杂度在 DDS、SPI 配置寄存器、双通道波形选择和输出时序。
3. 该名称比“DAC9767 驱动”更准确。

### 决策 2：第一版采用双通道独立 DDS

每个 DAC 通道拥有独立 DDS 配置：

1. `enable`
2. `wave_sel`
3. `fword`
4. `phase_init`

原因：

1. 满足两个通道输出不同频率、不同波形的需求。
2. 避免旧例程中 `DACB_DATA = DACA_DATA` 的限制。
3. 后续可扩展同步更新和相位关系控制。

### 决策 3：正弦波使用 ROM，方波和三角波使用逻辑生成

原因：

1. 正弦波用 LUT 实现简单稳定。
2. 方波可由相位最高位直接生成。
3. 三角波可由相位高位折返生成。
4. 方波和三角波不占用 ROM，更节省资源。

### 决策 4：SPI 使用固定 40-bit 帧

帧格式：

```text
[ CMD 8-bit ][ DATA 32-bit ]
```

原因：

1. MCU 端实现简单。
2. FPGA 端解析简单。
3. 32-bit 数据宽度与 DDS 频率字、初相位天然匹配。

### 决策 5：旧 Quartus 13 IP 不直接复用

不建议直接复用：

1. `pll.v`
2. `ddsrom.v`

原因：

1. 当前项目使用 Quartus 25.1。
2. 旧 IP wrapper 可能存在版本兼容和路径问题。
3. PLL 和 ROM 应优先在当前 Quartus 版本下重新生成或使用可综合 RTL 封装。

### 决策 6：文档先行

先建立：

1. `DOC/architecture.md`
2. `DOC/register_map.md`
3. `DOC/design_decisions.md`
4. `DOC/change_log.md`

原因：

1. 明确 FPGA 与 MCU 的接口合同。
2. 降低后续 RTL 返工。
3. 满足项目“代码修改必须留痕”的协作准则。

### 决策 7：SPI 控制优先，按键作为调试入口

第一版中 SPI 是正式控制入口。按键只作为本地调试入口，并通过全局寄存器中的 `key_ctrl_enable` 控制是否启用。

原因：

1. MCU 通过 SPI 写配置寄存器更适合正式系统集成。
2. 按键适合作为脱离 MCU 时的基础验证方式。
3. SPI 可控制是否启用按键调试，避免两套控制来源长期冲突。

### 决策 8：SPI 读数据同帧返回

第一版 SPI 读操作采用同一帧返回。

帧格式：

```text
[ CMD 8-bit ][ DATA 32-bit ]
```

读帧中 FPGA 在 `DATA` 阶段移出寄存器值。

### 决策 9：第一版频率字按 100 MHz DDS 时钟计算

文档和默认调试频率字先按 `100 MHz` DDS/DAC 时钟计算。

注意：

1. 当前第一批 RTL 暂时直接使用 `CLK50M` 作为内部时钟。
2. 后续集成 Quartus PLL 后，需要把 DDS/DAC 时钟切换到 100 MHz。
3. 如果板级最终使用其他频率，`Fword` 计算和按键预设表必须同步更新。
